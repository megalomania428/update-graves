# Этап 3. Эксперты и итог

<!-- markdownlint-disable-file MD013 -->

- Подготовить задания всей академии по `references/review-cycle.md` с теми же файлами, что у редакции, включая `deferred.md`, если он есть.
  - После условного компакта запустить академию: она один раз проверяет утверждённую версию плана целиком.
  - До открытия плана каждый эксперт пишет набросок в `plan-expert-3-<N>-<модель>.md` по правилам ревьюера из `references/stage-2.md`. Каждый сам запускает валидатор и проверяет все пункты `deferred.md`.
- Задача роли `эксперт` – проверить план по `task.md`, `decisions.md` и `autonomous-decisions.md`, а не по его внутренней логике: каждое требование свести к месту плана или к замечанию «не учтено», искать сценарии, в которых прогоны `/skill:spawn-spec-comsplit2-02` по заданиям столкнутся, застрянут или дадут неверный итог при соблюдении плана.
- Замечания экспертов разбирать так:
  - Принятые исправлять новой версией плана по `references/stage-2.md`, включая ворота валидатора. Порядок проверки задают пункты ниже, а не правило полного раунда этапа 2.
    - Изменение нарезки требует полного раунда редакции и повторного утверждения мной.
  - По отклонённым сразу проводить консультацию со всей доступной редакцией по `references/review-cycle.md`. Если отклонение остаётся в силе, закрыть замечание; иначе исправить по общему правилу.
    - Эксперта повторно не вызывать, кроме передачи автору понижения или отклонения `CRIT`. Его ответ считается единственной перепроверкой этого замечания.
  - `INFO` после исправления проверяет оркестратор по `plan-v<N>-changes.diff`.
  - `WARN` перепроверяет доступный ревьюер редакции по правилам перепроверки автором из `references/review-cycle.md`, с файлом замечаний эксперта вместо своего. Выбор ревьюера записать в журнал.
  - `CRIT` после исправления один раз перепроверяет только эксперт, который его нашёл.
    - Если эксперт недоступен, уже ответил на понижение или отклонение либо оставил `NOT ADDRESSED`, нужен полный раунд редакции.
  - Механизм, переписанный заново, проверяет редакция полным раундом.
- Цикл продолжается, пока замечания экспертов не закрыты, нарезка текущей версии не утверждена мной, а оркестратор не считает план соответствующим `task.md`, `decisions.md` и `autonomous-decisions.md`.
- В конце в последний раз выполнить ворота валидатора на итоговой версии, записать её хеш `digest` в журнал как итоговый и закоммитить каталог прогона скриптом `scripts/commit-specs.sh`.
- Итоговый ответ мне:
  - путь итоговой версии плана и её хеш;
  - задания по волнам с владельцами и строки запуска из обзора;
  - протокол слияния из обзора;
  - вывод валидатора и отметка о полноте инвентаризации;
  - раздел «Решено без тебя» по `references/autonomy.md`.
