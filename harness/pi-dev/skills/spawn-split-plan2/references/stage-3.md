# Этап 3. Эксперты и итог

<!-- cspell:ignore inventory нарезка нарезки ревьюер ревьюера ревьюерами ревьюеры валидатор валидатора закоммитить -->
<!-- markdownlint-disable-file MD013 -->

- Подготовить задания паре `эксперт` по `references/review-cycle.md` с теми же файлами, что у компашки, плюс `deferred.md`, если он есть, выполнить условный компакт и запустить пару: она один раз проверяет утверждённую версию плана целиком. До открытия плана каждая модель пишет набросок в `plan-expert-3-<N>-<модель>.md` по правилам наброска ревьюера из `references/stage-2.md`, сама запускает валидатор и проверяет каждый пункт `deferred.md`.
- Задача роли `эксперт` – проверить план по `task.md`, `decisions.md` и `autonomous-decisions.md`, а не по его внутренней логике: каждое требование свести к месту плана или к замечанию «не учтено», искать сценарии, в которых прогоны `/skill:spawn-spec-comsplit2-02` по заданиям столкнутся, застрянут или дадут неверный итог при соблюдении плана.
- Замечания экспертов разбирать так:
  - принятые исправлять новой версией плана по `references/stage-2.md`, включая ворота валидатора; порядок проверки исправлений задают пункты ниже, а не правило полного раунда из `references/stage-2.md`; изменение нарезки – полный раунд компашки и снова вопрос мне об утверждении нарезки;
  - по отклонённым оркестратором сразу проводить консультацию по `references/review-cycle.md` со всеми работающими ревьюерами компашки, эксперта повторно не вызывать, кроме передачи автору понижения или отклонения `CRIT`: этот ответ – его единственная перепроверка по этому замечанию. При отклонении замечание закрыто, иначе исправляется по общему правилу;
  - `INFO` после исправления проверяет оркестратор по `plan-v<N>-changes.diff`;
  - `WARN` после исправления перепроверяет одна работающая модель компашки по правилам перепроверки автором из `references/review-cycle.md`, с файлом замечаний эксперта вместо своего; выбор модели записывается в журнал;
  - `CRIT` после исправления один раз перепроверяет только нашедшая его модель-эксперт; если она недоступна или уже ответила на понижение или отклонение этого `CRIT`, его проверяет полный раунд компашки; оставшийся `NOT ADDRESSED` – тоже полный раунд компашки;
  - механизм, переписанный заново, – полный раунд компашки.
- Цикл продолжается, пока замечания экспертов не закрыты, нарезка текущей версии не утверждена мной, а оркестратор не считает план соответствующим `task.md`, `decisions.md` и `autonomous-decisions.md`.
- В конце в последний раз выполнить ворота валидатора на итоговой версии, записать её хеш `digest` в журнал как итоговый и закоммитить каталог прогона скриптом `scripts/commit-specs.sh`.
- Итоговый ответ мне:
  - путь итоговой версии плана и её хеш;
  - задания по волнам с владельцами и строки запуска из обзора;
  - протокол слияния из обзора;
  - вывод валидатора и отметка о полноте инвентаризации;
  - раздел «Решено без тебя» по `references/autonomy.md`.
