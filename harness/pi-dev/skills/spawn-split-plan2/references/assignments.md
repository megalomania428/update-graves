# Задания ролям

Действует на всех этапах.

- Все роли запускать через `spawn_subsession`, передавая модель роли в параметре `model`. Перед каждым запуском отдельной подсессии или параллельной пачки выполнять условный компакт по `references/context.md`; это относится также к повтору после `BLOCKED`, замене модели из-за лимитов и консультации.
- Работа идёт на лэптопе: в каждом задании для любой роли запрещать установку чего-либо на лэптоп, длительные тяжёлые тесты и сборки; разрешение на них действует, только если я дал его явно, и передаётся в задании дословно. Инвентаризация по `references/remote.md` выполняется на хосте прогонов, а не на лэптопе, и этим запретом не ограничена.
- В каждом задании для любой роли явно запрещать инструменты `spawn_*`, чтобы роль работала в одиночку.
- `TREE` все роли только читают: ничего в нём не создают, не изменяют, не удаляют и не коммитят, веток и worktree не создают, сборок и тестов в нём не запускают. Свои файлы роли пишут только по путям из задания в каталог прогона. PI WEB запускает подсессии в каталоге оркестратора, поэтому в каждом задании для любой роли указывать:
  - абсолютные `TREE` и `BASE`; команды по дереву выполнять через `git -C "${TREE}"`, а содержимое на `BASE` читать командой `git -C "${TREE}" show "${BASE}:<путь>"`, если рабочее дерево отличается от `BASE`;
  - пути к файлам абсолютными;
  - основную рабочую копию проекта, если это не `TREE`, и общие рабочие копии внешних репозиториев не трогать.
- Репозитории GitHub все роли, включая `оркестратор`, изучают только локально: сначала искать клон в `/workspace/github/<репо>`, а если его нет – выполнить `git -C /workspace/github clone https://github.com/<владелец>/<репо>`. Исключение – репозитории больше гигабайта: перед клонированием сверить размер в КБ через `curl -s https://api.github.com/repos/<владелец>/<репо> | jq .size`, и при значении больше `1048576` не клонировать, а изучать удалённо. Найденный клон обновлять только `git fetch`. В каждом задании для любой роли указывать это правило явно.
- Артефакты передавать ролям путями к файлам в каталоге прогона, а не вставлять их содержимое в текст задания.
- Правила файлов скилла передавать ролям абсолютным путём файла литералом с названием раздела, а скрипты скилла – абсолютным путём литералом с подставленным значением `SKILL_DIR`: относительные `references/…` и `scripts/…` и переменная `SKILL_DIR` адресованы оркестратору, подсессия их не раскроет. Вместе со скриптом передавать аргументы и правило: при ненулевом коде записать в свой отчёт путь скрипта, аргументы, код и stderr как ошибку, не использовать stdout как результат и не выдавать сбой за «не найдено».
- Задание скауту на поиск прецедентов: запустить `precedents.sh` с проектом прогона, текущим `RUN_REL` и ключевыми словами из задания, просматривать прогоны от новых к старым без произвольного лимита, не останавливаясь на первом кандидате, и для кандидатов читать полный контекст вопроса и ответа в `decisions.md` и `task.md`. Для каждой применимой записи вернуть `путь:строка`, `RUN_REL`, дату решения и её источник – дату в самой записи либо дату каталога прогона как явно обозначенную резервную, – вопрос и ответ дословно. Совпадение слов в `task.md` ответом не считать, записи `autonomous-decisions.md` других прогонов помечать как автономные решения. Если применимого нет – «не найдено» и использованные ключевые слова.
- Задание скауту на инвентаризацию – по `references/remote.md`: передать абсолютные `TREE`, `BASE`, путь монолита относительно `TREE`, язык, значение `--grammar` или пустую строку, путь скрипта и выходные пути `inventory-<N>.json` и `inventory-<N>.log`, а правила удалённого прогона – абсолютным путём `references/remote.md` литералом.
- Скауты пишут найденное со ссылками `путь:строка` в файл из задания и в ответе возвращают одну строку: статус и суть.
- Задания ролям `ревьюер` и `эксперт`, разбор их вердиктов, `BLOCKED`, `DISPUTED` и консультации – по `references/review-cycle.md`.
