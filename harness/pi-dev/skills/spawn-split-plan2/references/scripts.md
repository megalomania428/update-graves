# Скрипты

Действует на всех этапах.

Скрипты лежат в `SKILL_DIR/scripts/`, принимают абсолютные пути и заменяют ручные команды git, `diff` и `sha256sum`. Вызывать по абсолютному пути: `"${SKILL_DIR}/scripts/<имя>.sh"` и `python3 "${SKILL_DIR}/scripts/validate-plan.py"`; каждый вызов bash – новая оболочка, поэтому значения прошлых вызовов передавать литералами из журнала или `context-state.md`. `precedents.sh` и `inventory.sh` запускают скауты, `validate-plan.py` – оркестратор, ревьюеры и эксперты, остальные – оркестратор; поручение роли запустить скрипт – по `references/assignments.md`.

- Код возврата: `0` – успех, `2` – неверные аргументы или нарушенное предусловие, `1` у `validate-plan.py` – найдены ошибки плана, другие ненулевые коды – сбой шага. Сообщения – в stderr, результат – в stdout и только при успехе.
- При ненулевом коде вывод не использовать, записать в журнал скрипт, аргументы, код и сообщение и действовать по правилам этапа. Ручной обход запрещён: не выполнять вместо скрипта `git commit`, `git add`, `diff`, `sha256sum` и подобные команды и не подставлять старые хеши. Если причину можно устранить без изменения чужих данных, например выбрать другое краткое имя, исправить аргументы и вызвать скрипт снова.

Аргументы и вывод:

- `run-dir.sh <MAIN_DIR> <SPECS_REPO> <краткое-имя> [<тема>]` – создаёт каталог прогона и печатает `RUN_REL`. Краткое имя и тема – строчные латинские буквы, цифры и одиночные дефисы, тема – один подкаталог. `MAIN_DIR` – основная рабочая копия, связанный worktree – код `2`.
- `precedents.sh <владелец>/<репо> <RUN_REL> [<ключевое слово>…]` – прецеденты по `references/autonomy.md`: прогоны `SPECS_REPO` с `decisions.md` или `task.md` от новых к старым, прогоны этого проекта помечены `*`, текущий `RUN_REL` и вложенные прогоны исключены. Без ключевых слов печатает список прогонов, с ними – строки этих файлов с любым из слов без учёта регистра в виде `файл:строка:текст`; без локали `C.UTF-8` с регистром кириллицы – ошибка до поиска.
- `inventory.sh <файл> <язык> <имя> [<грамматика>]` – инвентаризация монолита в одноразовом контейнере podman: образ `mirror.gcr.io/library/python:3.13.18-slim`, закреплённый digest индекса, или значение переменной `INVENTORY_IMAGE`, внутри – установка закреплённых пакетов tree-sitter и грамматики языка без сборки из исходников, затем `inventory.py`. `<файл>` – абсолютный путь к копии монолита, `<язык>` – ключ таблицы языков `inventory.py` или, с `<грамматикой>`, любой ключ из строчных латинских букв, цифр и `_`, `<грамматика>` – значение `--grammar` `inventory.py`, `<имя>` – путь монолита относительно `TREE` для поля `path` вывода. Печатает JSON инвентаризации; вывод установки пакетов – в stderr. Нужны podman и сеть до реестра и PyPI, поэтому запускается только на хосте прогонов по `references/remote.md`.
- `inventory.py` – сам разбор, stdlib Python 3 и модули tree-sitter из контейнера: `inventory.py [--display <имя>] [--grammar <пакет>] [--no-tree-sitter] <файл> <язык>` печатает JSON инвентаризации, `inventory.py --requirements <язык> [--grammar <пакет>]` – строки требований pip. Таблица языков с закреплёнными пакетами грамматик и узлами импортов, комментариев и контейнеров – `LANGUAGES` в начале скрипта; tags-запрос берётся из `TAGS_QUERY` пакета, а без него – из файла `queries/tags.scm` пакета. Общий режим для языка вне таблицы – `--grammar tree-sitter-<имя>==<версия>[@<функция>]`: модуль – имя пакета с `_` вместо `-`, функция языка по умолчанию `language`, контейнеры – виды `class`, `enum`, `interface`, `module`, `object`, комментарии – узлы `comment`; узлы импортов общему режиму неизвестны, поэтому импорты попадают в `statements`. Ключ языка из таблицы с `--grammar`, неверная строка `--grammar` и неизвестный язык без неё – код `2`; пакет без tags-запроса – ошибка с кодом `1`. Флаг `--no-tree-sitter` оставляет только слой `ast`/`symtable` для Python и нужен тестам без контейнера. Формат вывода – в `references/plan-format.md`.
- `validate-plan.py <каталог-плана> [--inventory <inventory.json>] [--tree <TREE>]` – проверка `plan.json` и файлов плана по правилам `references/plan-format.md`, в объёме, который там перечислен, пункты раздела «Входит» – по описанию раздела `## Входит` в `references/plan-format.md`; режимы с `--tree`: один `--tree` – ещё SHA256 исходника на `BASE`, который валидатор читает сам командой `git -C <TREE> show <base>:<source.path>` и сверяет с `source.sha256`; `--inventory` вместе с `--tree` – то же и ещё совпадение `source` и `sha256` с инвентаризацией, отсутствие синтаксических ошибок, полнота и единственность распределения деклараций и операторов верхнего уровня, один владелец у деклараций с общим диапазоном и их диапазоны в заданиях; `--inventory` без `--tree` и `--tree` не каталогом – код `2`, нечитаемый исходник на `BASE` или отсутствие `git` – ошибка плана. Успех – строка `ok: <число> tasks (waves 1/<число>/1)` и код `0`; ошибки плана – все найденные строки `error: …` в stderr и код `1`; неверные аргументы, отсутствующий каталог плана, нечитаемая или неверная инвентаризация – код `2`.
- `plan-files.sh` – манифесты и изменения версий плана:
  - `manifest <каталог>` – отсортированные строки из `<SHA256>`, двух пробелов и `<путь>` для всех файлов каталога в формате `sha256sum --check`; пустой каталог, ссылки, другие нерегулярные файлы и имена с переводом строки или обратной косой чертой – код `2`;
  - `digest <каталог>` – одна строка: SHA256 вывода `manifest`; это хеш версии плана для журнала и одобрения;
  - `changes <RUN_DIR> <старая-версия> <новая-версия> <OUT>` – пишет в новый файл `OUT` `diff -ruN plan-v<старая> plan-v<новая>` из `RUN_DIR` и печатает путь; версии – двузначные номера, существующий `OUT` – код `2`.
- `commit-specs.sh <RUN_DIR>` – добавляет каталог прогона в индекс и коммитит только его: сообщение `add <RUN_REL> spec` для первого коммита каталога, `update <RUN_REL> spec` для остальных, и печатает SHA коммита; без изменений ничего не коммитит и печатает в stderr `nothing to commit` с кодом `0`. `RUN_DIR` передавать ровно как `${SPECS_REPO}/${RUN_REL}`.

Правила коммитов:

- коммитит только роль `оркестратор` и только в репозиторий спек: после каждой подсессии роли, изменившей файлы в каталоге прогона, после каждой версии плана и в конце прогона; в проект планировщик не коммитит;
- автор и коммитер – из раздела «Роли» `SKILL.md`, а не из `git config`; коммиты без криптоподписи; в коммит попадает только каталог прогона, чужие изменения репозитория спек не трогать;
- добавлять `Co-Authored-By` и любые другие трейлеры с упоминанием моделей запрещено.
