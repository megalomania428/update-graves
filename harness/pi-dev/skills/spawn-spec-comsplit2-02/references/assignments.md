# Задания ролям

<!-- cspell:ignore subsession venv доработчик коммитить лэптопе подсессии ревьюер ревьюера репо спеке -->
<!-- markdownlint-disable-file MD013 -->

Действует на всех этапах.

- Все роли запускать через `spawn_subsession`, передавая модель роли в параметре `model`. Перед каждым запуском отдельной подсессии или параллельной пачки выполнять условный компакт по `references/context.md`; это относится также к повтору после `BLOCKED`, замене модели из-за лимитов и консультации.
- Работа идёт на лэптопе: в каждой спеке для любой роли запрещать длительные тяжёлые тесты, если я явно не разрешил их; разрешение действует только на названные мной команды и объём и передаётся в задании дословно.
- В каждой спеке для любой роли явно запрещать инструменты `spawn_*`, чтобы роль работала в одиночку.
- С файлами проекта все роли работают только в worktree `WT_DIR` из этапа 1, а свои файлы пишут по путям из задания в каталог прогона. Дополнительные рабочие каталоги и worktree допускаются только для операций, прямо предусмотренных инструкциями проекта (`AGENTS.md`, `CLAUDE.md` и подобными), и для временного каталога прогона ревьюера по `references/stage-2.md`; подготовку и очистку каталогов по инструкциям проекта обеспечивает оркестратор, а свой временный каталог ревьюер создаёт и удаляет сам. PI WEB запускает подсессии в каталоге оркестратора, поэтому в каждом задании для любой роли указывать:
  - абсолютный `WT_DIR` и разрешённые дополнительные рабочие каталоги, если они нужны;
  - команды проекта выполнять через `cd "${WT_DIR}" &&` или `git -C "${WT_DIR}"`; для операций в других разрешённых каталогах явно задавать соответствующий абсолютный рабочий каталог;
  - пути к файлам писать абсолютными; файлы проекта изменять внутри `WT_DIR`, операции в дополнительных каталогах выполнять только в пределах, разрешённых инструкциями проекта и ролью;
  - основную рабочую копию проекта и общие рабочие копии внешних репозиториев не трогать;
  - установка зависимостей (`node_modules`, venv и подобное) разрешена внутри `WT_DIR`, во временном каталоге прогона ревьюера либо в дополнительных каталогах, прямо назначенных для этого инструкциями проекта.
- В каждой спеке для ролей `исполнитель` и `доработчик` указывать: веток и worktree самостоятельно не создавать, использовать только подготовленные оркестратором рабочие каталоги; в проекте и дополнительных worktree ничего не коммитить.
- Репозитории GitHub все роли, включая `оркестратор`, изучают только локально: сначала искать клон в `/workspace/github/<репо>`, а если его нет – выполнить `git -C /workspace/github clone https://github.com/<владелец>/<репо>`. Исключение – репозитории больше гигабайта: перед клонированием сверить размер в КБ через `curl -s https://api.github.com/repos/<владелец>/<репо> | jq .size`, и при значении больше `1048576` не клонировать, а изучать удалённо. В каждой спеке для любой роли указывать это правило явно.
- Артефакты передавать ролям путями к файлам в каталоге прогона, а не вставлять их содержимое в текст задания.
- Задания ролям `ревьюер` и `эксперт`, разбор их вердиктов, `BLOCKED`, `DISPUTED` и консультации – по `references/review-cycle.md`.
- Роли `исполнитель` и `доработчик` пишут полный отчёт в файл, путь к которому указан в задании: что сделано, какие проверки запускались с командами и результатами, отклонения от спеки, сомнения. В ответе возвращают только статус и одну строку сути:
  - `DONE` – сделано;
  - `DONE_WITH_CONCERNS` – сделано, но есть сомнения: прочитать их в отчёте до проверки;
  - `NEEDS_CONTEXT` – не хватает информации: дополнить задание и запустить роль заново;
  - `BLOCKED` – выполнить невозможно: если проблема в спеке этапа 2, вернуться к этапу 1 или 2, если в спеке исправлений – исправить её саму и запустить роль заново.
