# Вопросы мне и решения без меня

Действует на всех этапах.

## Вопросы

- Все вопросы мне, включая уточнения, согласования, продолжение после 33 раундов и остановки по ошибкам, задавать только через `ask_user`. Текстовое сообщение с вопросом вместо вызова инструмента запрещено. Готовые независимые вопросы объединять в один вызов; вызывать `ask_user` единственным инструментом в сообщении и последним действием хода, затем ждать ответа. Не повторять отправленные вопросы; оставленные без ответа считать открытыми, не подставлять рекомендуемый вариант молча. Исключение – блок, пропущенный целиком, без ответа ни на один вопрос: скорее всего, его вытеснил вызов нового блока, поэтому такой блок отправить повторно.
- Спрашивать меня можно только в этих случаях:
  - развилки этапа 1 – не больше трёх раундов вопросов за прогон;
  - противоречие между моими явными решениями в `task.md` и `decisions.md`;
  - действие необратимое или видимое за пределами `WT_DIR` и каталога прогона;
  - недоступны все модели роли, повторный `BLOCKED`, недостающее вне списка передаваемых файлов, ошибка `scripts/worktree.sh` или расхождение снимка основной рабочей копии;
  - лимит раундов ниже.
- Каждый цикл с ролями – ревью спеки, доработка, финальное ревью – не больше 33 раундов подряд, лимит считается для каждого цикла отдельно. После 33 раунда с незакрытыми замечаниями сохранить их, выполнить условный компакт по `references/context.md`, затем через `ask_user` показать оставшиеся замечания и спросить, продолжать или нет. Это ограничение числа раундов, а не периодичность компакта; без разрешения следующий раунд не запускать.

## Решения без меня

- Остальное оркестратор решает сам: развилки после трёх раундов вопросов, толкование задания и инструкций проекта, отклонённые и спорные замечания ревьюеров и экспертов.
- Сначала искать решение, которое не отступает от `task.md`, `decisions.md` и инструкций проекта (`AGENTS.md`, `CLAUDE.md` и подобных). Отступать только тогда, когда такого решения нет.
- Искать прецеденты командой `scripts/precedents.sh "${SPECS_REPO}" <владелец>/<репо> [<ключевое слово>…]`: она выводит мои ответы прошлых прогонов от новых к старым, прогоны этого проекта помечены `*`. Свежее решение весит больше старого, при близких датах – решение по этому же проекту; при противоречии побеждает свежее. Вопрос себе: как ответил бы я, судя по этим решениям.
- Если решение отступает от инструкций проекта или опирается на спорное толкование, собрать доводы всех работающих ревьюеров консультацией по `references/review-cycle.md`, без экспертов. Решать по существу доводов, а не по их числу.
- Каждое такое решение записать в `autonomous-decisions.md`: вопрос, решение, основание – прецедент с `RUN_REL` и датой, доводы ревьюеров или рассуждение. Решение против большинства доводов пометить «вопреки ревьюерам». Остальные роли считают эти решения согласованными наравне с `decisions.md`.
- В итоговом ответе мне и при любой остановке прогона перечислить в разделе «Решено без тебя» все записи `autonomous-decisions.md` по одной строке с путём к файлу.
