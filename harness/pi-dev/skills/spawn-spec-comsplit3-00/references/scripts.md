Действует на всех этапах.

Скрипты лежат в `SKILL_DIR/scripts/`, запускаются Bash, требуют Git, GNU coreutils/findutils/grep/sort, для `run-dir.sh` и `worktree.sh` также `flock`; текстовый поиск требует доступную локаль `C.UTF-8`. Они принимают абсолютные пути каталогов и выходных файлов и заменяют ручные операции. Неверное число или проверяемый формат аргументов – код 2 с диагностикой на stderr; ошибки Git, файловой системы, зависимостей и отказ предусловий – ненулевой код, успех – 0. stdout – только результат, описанный ниже. При любом ненулевом результате остановить зависимые действия, сохранить команду, код, stderr и фактически оставшиеся артефакты, задать обязательный вопрос по `references/autonomy.md`. Ручной обход скрипта, повтор его операции отдельными командами и молчаливое продолжение запрещены. После согласованного исправления причины можно повторить сам скрипт; не удалять чужие данные или частично созданные ветки без согласования.

- `run-dir.sh <MAIN_DIR> <SPECS_REPO> <краткое-имя> [<тема>]` – создаёт каталог прогона и печатает `RUN_REL`. Короткое имя – строчные латинские буквы/цифры с внутренними дефисами, тема – относительные компоненты из букв/цифр/`_`/`-`; `SPECS_REPO` – корень Git. Симлинки в иерархии каталога прогона отклоняются до записи через них. Резервация атомарна между запусками скрипта. Следующий свободный двузначный `NN` и лимит 99 номеров считаются за день внутри выбранного каталога темы, а при отсутствии темы – внутри каталога проекта `<владелец>/<репо>`. Разные темы и корень проекта имеют независимые счётчики и могут иметь одинаковые `NN`, но полные `RUN_REL` различны. По исчерпании 99 номеров за день в выбранном каталоге – ошибка, трёхзначный номер не создаётся.
- `worktree.sh <MAIN_DIR> <слог репо> <слог задачи>` – проверяет, что основная рабочая копия чистая и `HEAD` не отсоединён, создаёт от `HEAD` ветку и worktree по правилам этапа 1 и печатает три строки: ветку, `WT_DIR` и `HEAD`. Выбор имени и создание сериализованы блокировкой общего Git-каталога. `WT_ROOT` – существующая переменная для тестового переопределения корня worktree, по умолчанию `/workspace/jobs/wtr4sdd`. Для настоящего запуска этапа 1 обеспечить отсутствие унаследованного `WT_ROOT` в окружении команды; переопределение использовать только для явно разрешённых удаляемых тестовых окружений. При ненулевом коде возврата остановиться и спросить пользователя.
- `snapshot.sh <каталог>` – печатает хеш дерева: снимок рабочего дерева без коммитов и без изменения индекса, неотслеживаемые файлы входят, игнорируемые – нет. Нужен существующий коммит `HEAD`. Снимок не меняет индекс, но записывает объекты в Git; техническому `scout` запрещён вызов на исходном `WT_DIR`.
- `review-bundle.sh <WT_DIR> <FROM> <TO> <OUT>` – пишет в новый `OUT` пакет для ревью между снимками `FROM` и `TO`: `git diff --stat` и `git diff -U10`. Родитель `OUT` должен существовать; файл пакета имеет приватные права 0600 для подсессий текущего пользователя; существующий файл не перезаписывается, ошибка не оставляет готовым частичный пакет.
- `spec-files.sh <каталог>` – печатает стабильно отсортированный манифест каталога вложений или правок строками `<SHA256> <путь>`. Вызывать только для существующих непустых каталогов обычных файлов; симлинки и специальные типы отклоняются с кодом 2 до выдачи манифеста; права перечислять в спеке отдельно, SHA256 содержимого их не покрывает.
- `precedents.sh <SPECS_REPO> <владелец>/<репо> [<ключевое слово>…]` – прецеденты по `references/autonomy.md`: прогоны с `decisions.md` или `task.md` от новых к старым по дате из имени каталога, прогоны этого проекта помечены `*`; без ключевых слов печатает список прогонов, с ними – совпавшие строки этих файлов без учёта регистра. Ключевые слова – буквальные непустые однострочные строки, объединённые по ИЛИ, не регулярные выражения. Нет совпадений – успех с пустым выводом; ошибки чтения – ненулевой код. Результаты содержат путь прогона и дату; исключение текущего и будущих прогонов при разборе – по `references/autonomy.md`.
- `commit-specs.sh <SPECS_REPO> <RUN_DIR>` – добавляет каталог прогона в индекс и коммитит только его: сообщение `add <RUN_REL> spec` для первого коммита каталога, `update <RUN_REL> spec` для остальных; без изменений ничего не коммитит и печатает `nothing to commit`.
- `commit-project.sh <WT_DIR> <сообщение> [<путь>…]` – единственный коммит в проект: без путей добавляет всё через `git add -A`, с путями – только их, сохраняя чужие ранее staged изменения вне списка; печатает SHA и сообщение коммита. Пути – буквальные относительно корня `WT_DIR`, без `..` и Git pathspec magic; директория означает весь её scope, поэтому предпочтительны конкретные одобренные файлы. Отсутствие изменений проекта – ошибка, второй итоговый коммит не создавать.

Правила коммитов:

- коммитит только роль `оркестратор`: в проект – один итоговый коммит в `WT_DIR` на этапе 4, в репозиторий спек – после каждой подсессии роли, изменившей файлы в каталоге прогона, и в конце прогона;
- автор и коммитер – по умолчанию имя `Moderator` и email `moderator@models.dev`, переопределяемые через `ORCH_NAME` и `ORCH_EMAIL`, а не из `git config`; в значении email угловые скобки запрещены; коммиты без криптоподписи; в коммит в репозиторий спек попадает только каталог прогона, чужие изменения там не трогать;
- добавлять `Co-Authored-By` и любые другие трейлеры с упоминанием моделей запрещено.
