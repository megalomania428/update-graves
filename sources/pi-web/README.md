# `@raven428/pi-web`

<!-- markdownlint-disable MD013 -->
<!-- cspell:ignore enum jmfederico patchset subkey subsession toolArgs toolContent subsessions virtualkeyboardpolicy Σtotal unrepaired -->

Patched build of [pi-web](https://github.com/jmfederico/pi-web), distributed as the `@raven428/pi-web` npm tarball in [GitHub Releases](https://github.com/megalomania428/update-graves/releases). The upstream ref and the patch number live in `build.yaml`: `ref: v1.202609.0` with `patch: 9` sets the package version to `1.202609.0-p9`. Pull requests and manual builds use `1.202609.0-p9.dev.<run>.<attempt>` and the shared `v999` draft.

Installation: `npm i -g <asset .tgz URL>`. For example:

```bash
npm i -g 'https://github.com/megalomania428/update-graves/releases/download/pi-web-v1.202609.0p9/pi-web-1_202609_0-p9.tgz'
```

The package requires Node.js >=22.19.0 and is not a standalone executable. Native dependencies such as `node-pty` can require build tools on the installation machine.

## List of patches

- `001-composer-send-binding` – backport of upstream `77c4f529` and `5275ca4d`: chat composer send bindings in Settings → Keyboard replace the Enter-key preference, app shortcuts accept single keys and sequences, and the keyboard send action while the agent is running is configurable; the send buttons keep working as before
  - `shortcuts.composer.send.desktop` – one key combination, `mod` means Ctrl/⌘, `null` disables keyboard sending; unset falls back to the browser-local Enter preference, Enter by default
  - `shortcuts.composer.send.mobile` – the same for touch or narrow screens (coarse pointer or viewport up to 760px); unset falls back to the browser-local Enter preference, Shift+Enter by default
  - `defaultStreamingBehavior` – `steer` (default) | `followUp`; during compaction keyboard sending always queues as `followUp`

```json
{
  "shortcuts": {
    "composer.send.desktop": "mod+enter"
  },
  "defaultStreamingBehavior": "steer"
}
```

- `002-chat-card-disclosure` – configurable disclosure (`none`/`live`/`last`/`all`) for thinking, skill, and tool-result/details/diff/arguments/written-content transcript cards, plus the eighth `eventsGroup` subkey for the summarizing events group card; remove the duplicate red error block while keeping error text in forced-open `Result`, and show failed live `edit` previews there until the final result replaces them
  - `ui.disclosure.thinking` – `none` (default) | `live` | `last` | `all`
  - `ui.disclosure.skillInvocation` – `none` (default) | `live` | `last` | `all`
  - `ui.disclosure.toolResult` – `none` (default) | `live` | `last` | `all`; `live`/`last` target the last call or standalone result that renders this card
  - `ui.disclosure.toolDetails` – `none` (default) | `live` | `last` | `all`; `live`/`last` target the last call that renders this card
  - `ui.disclosure.toolDiff` – `none` | `live` | `last` | `all` (default); `live`/`last` target the last call that renders this card
  - `ui.disclosure.toolArgs` – `none` (default) | `live` | `last` | `all`; `live`/`last` target the last call that renders this card
  - `ui.disclosure.toolContent` – `none` | `live` | `last` | `all` (default); `live`/`last` target the last call that renders this card
  - `ui.disclosure.eventsGroup` – `live` (default) | `last` | `all` (`none` is not accepted)

```json
{
  "ui": {
    "disclosure": {
      "thinking": "all",
      "skillInvocation": "none",
      "toolResult": "last",
      "toolDetails": "none",
      "toolDiff": "all",
      "toolArgs": "none",
      "toolContent": "all",
      "eventsGroup": "last"
    }
  }
}
```

## Session archive conversion

`pi-web-convert-session-archive-<version>.py`, a separate asset of the same release, converts the session archive of a data directory between the old and the new layout and imports opencode sessions into the new one. Stop PI WEB before running it: the script does not check whether the session daemon is running.

- `python3 pi-web-convert-session-archive-1_202609_0-p9.py [--data-dir DIR] [--dry-run]` – moves `archived-sessions.json` with `archived-sessions/` into `archived-projects/`; after every record and file is converted without problems the index is renamed to `archived-sessions.json.migrated-<UTC time>`, otherwise the records that were not converted stay in it for the next run; session files without an index record are added from their header
- `--name-unnamed [--pi PATH] [--model PROVIDER/MODEL] [--name-limit N] [--name-timeout SECONDS]` – in the same run names unnamed sessions from their first user message with `pi -p --no-session --no-tools --no-extensions --no-skills --no-context-files` and the prompts of the pi-web title generator removed by `003-agent-session-title`, then appends the name to the session file as pi does; a failed or empty answer leaves the session unnamed, and so does a read-only session file, with a warning
- `--reverse` – moves `archived-projects/` back into `archived-sessions/` and merges the records into `archived-sessions.json` without replacing records already there
- `--repair` – reconciles `archived-projects/`: adds records for session files without one, drops records without a file, moves session files and records into the day and month of their creation time from the session id, the file name or the session header, takes the name from the last `session_info` of the file when it has one, removes an archived file with its record when its `originalPath` holds the same contents, as an interrupted archive or restore leaves it, warns about an archived file and its original when one is a strict prefix of the other and keeps both, looks for the original of a file without a record next to the other recorded originals and warns when an `originalPath` exists with other contents or is only a guess; it also cleans up after an interrupted operation: puts a summary back from its hidden backup when the summary is missing, removes the other backups, summary temp files and unfinished `.copying` copies in the archive, in `archived-sessions/` and next to recorded original paths, removes a `*.moving` file identical to the archived session file or the original it belongs to, which is looked for next to the recorded original paths and in the session directory of the project computed as pi does (`PI_WEB_AGENT_SESSION_DIR`, `PI_CODING_AGENT_SESSION_DIR`, `sessionDir` in the project and agent `settings.json`, else `sessions/--<project>--` in the agent directory from `PI_WEB_AGENT_DIR`, `PI_CODING_AGENT_DIR`, `agent.dir` of the PI WEB config or `~/.pi/agent`), and reports the other `*.moving` files, where one whose original is not found stays in place with a warning; run it with PI WEB stopped after PI WEB was killed while archiving, restoring or renaming or reported a failed undo
- `--opencode DB [--name-unnamed …]` – imports the sessions of an opencode SQLite database into `archived-projects/`; run it with opencode quit: the database is opened read-only as immutable and left as is, and one whose `-wal` file is not empty is refused; every session with messages, archived in opencode or not, becomes an archived pi session file `<creation time>_<opencode session id>.jsonl` keeping the opencode id, with the opencode session directory as cwd (a child session in another directory gets that of its root session) and `archivedAt` from the opencode archive time or else its last update; a child session started by the opencode `task` tool becomes a separate session with its parent in `parentSession` and `parentSessionPath` and goes into the project of its parent even when it ran in another directory; user and assistant text, reasoning, tool calls with their arguments and full results, images, model changes, token usage, cost and errors are kept, token usage sums all steps of an opencode message with reasoning counted in the output, other attachments become a note with their type and, when embedded, size, and every opencode compaction with a summary becomes a pi `compaction` entry with the model change, reasoning and error of the summarizing message while all the messages stay in the file; tool metadata such as diffs and diagnostics, file snapshots, patches, todo lists, UI events and share data are dropped; a real opencode title becomes the session name, while a session with the default `New session - <time>` or `Child session - <time>` title stays unnamed unless `--name-unnamed` names it; sessions without messages are skipped, and a session already in the archive with its file is counted as present and left as is, except that `--name-unnamed` names it when it is unnamed; a session whose file lies at the original path of its summary record, as after a restore, or moved back to `archived-sessions/` by `--reverse` is counted as present too and is never named; a child of a session that is skipped or not imported because of a problem gets no parent; at the end every session directory that is not a PI WEB project gets a warning with its number of sessions, since PI WEB shows archived sessions only under their project

`--data-dir` defaults to `PI_WEB_DATA_DIR` or `~/.pi-web`. Every run can be repeated, and an interrupted run, including one cut by a power loss, is first repeated as is: a run stopped by an error or Ctrl+C keeps the records of the files it has already moved, and `--repair` after it picks up a file moved right before the stop. `--dry-run` only reports; the exit code is 1 when a problem left a file or record unconverted or unrepaired or a session with messages not imported, while warnings keep both files and leave it 0. Every 5 seconds or so, between sessions, records and opencode messages, a run prints `processed N/TOTAL` with the counters so far, without the total in `--repair`, and `--name-unnamed` prints `naming <file>…` before every pi call.
